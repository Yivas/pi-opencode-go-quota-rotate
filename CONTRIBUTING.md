# Contributing

Issues and pull requests are accepted. The current scope is proposals and documentation; there is no executable release, runtime baseline or build/test command yet. Implementation proposals should be discussed in an issue before opening a code pull request.

Search existing issues first. Use the issue forms for a documentation problem or a proposal. Include the affected commit/file, Pi and operating-system context when relevant, a sanitized reproduction, and expected versus observed behavior. Use “not applicable” for runtime fields when reporting a documentation problem.

Never include API keys, account identifiers, prompts, transcripts, private configuration or raw provider logs. Report vulnerabilities through [SECURITY.md](SECURITY.md).

For a pull request, describe the change, why it is needed and the checks performed. Check relative links and factual claims; do not invent installation commands or compatibility. Runtime changes must define tests once implementation is in scope. Keep changes focused and explain any compatibility or privacy risks. Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

No review or release deadline is guaranteed.
